---
description: 交接就绪检查——校验并优化当前项目的交接文档,确保新 agent 能凭它完整接手
---

先整篇读 skill 目录 guides/handoff-authoring.md 与 guides/acceptance.md,按其标准执行。对当前工作空间执行交接就绪检查(用户已确定要交接)。逐项检查、输出 PASS/FAIL 报告,能修的当场修:

0.5 **前提**:项目还没有 brain(无 `.brain/` 也无 `.brain-home`)→ 先执行 /brain-init 完整流程(含三源考古),再回本流程继续。
1. **HANDOFF.md 完整性**:`.brain/HANDOFF.md`(或 `.brain-home` 指向的归属仓库)存在;五段(这是什么/资产与访问/阅读顺序/如何验证/雷区)都有实质内容;列出所有残留 TODO。
1.5 **会话清扫(交接是末班车,必做)**:按 brain-init 第 3 步的九类标准对**整个会话历史**做最后一次提取——职责边界、被否方案、口头雷区、任务三态、学习进度、未解决阻塞——凡未落盘的,按分类表落盘(HANDOFF/TASKS/CONVENTIONS/wiki)。会话被压缩过时,先读原始 session 记录补全(路径见 brain-init 命令),读不到必须在交接报告注明"会话知识可能不完整"。
2. **快照污染扫描**:HANDOFF 及其他稳定文档中不应出现会过期的快照值(commit 哈希、版本号、"当前部署是X")——发现就改写成"怎么查"的方法。证据记录(evidence.jsonl)里的快照是合法的,不算污染。
3. **验证命令实跑**:把"如何验证已接管成功"里的每条命令真实执行一遍,失败的要么修命令要么修现实。
4. **状态一致性**:TASKS.md 与实际进行中的事一致;evidence 最后一条与 `git log` 对得上;工作树无未提交变更(有则先提交)。
5. **wiki 健康**:若有 `.brain/wiki/`,index.md 与词条文件一一对应;本次会话若有高重获成本认知未入库,现在补。
6. **密钥纪律**:全部文档 grep 检查无密钥明文;只有位置指引。
6.5 **验收契约核对**:项目若有 .brain/HANDOFF_ACCEPTANCE.md,核对验收项是否覆盖当前全部资产(资产变了验收没跟上=未就绪);没有该文件则按 acceptance 指南提议生成。
7. **收尾**:所有修正 commit;交接文档必须到达远端才算真正可交接,因此按本机规范 commit 后**立即 push**(机主明示禁推的仓库除外,此时结论降为"仅本地就绪,远端未同步")。输出最终报告:每项 PASS/FAIL、修了什么、接手方拿到仓库后的第一条命令是什么。

报告以"交接就绪"或"交接未就绪(缺X)"作为第一行结论。
