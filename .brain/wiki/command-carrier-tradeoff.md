# 命令载体选型:提示词、skill、hook、原生命令的完整决策链(深度研究)

## 问题是什么

project-brains 的五个命令(brain-init/takeover/handoff/handoff-show/backfill)该用什么载体实现?
用户先后追问了四轮:为什么是"自定义提示词"而不是"自定义指令"?Trellis/OpenSpec 提供的
"指令"为什么它们可以?/compact 是执行压缩逻辑而不是发文本,init 不是一个道理吗?
Trellis 的 `$trellis-start` 那种 skill 形态我们为什么不用?——四问合起来其实是同一个设计问题:
**一个能力应该用什么载体,由什么决定?**

## 结论(决策链)

两步判断,每个格子放对东西:

**第一问:这件事需不需要判断力?**
- 需要(读懂陌生项目、评估交接质量、决定什么值得沉淀)→ 载体只能是**给模型的指令文本**。
  写不成确定性代码:没有算法能判定"这份 HANDOFF 够不够零上下文者接管"。
- 不需要(检测文件存在、比对时间戳、加解密、拦截事件)→ 载体必须是**代码**,
  因为代码不受话术影响——"别记了我赶时间"骗得过模型,骗不过 Stop hook。

**第二问(文本类):谁该扣扳机?**
- 每次会话都要 → 常驻注入(宪法,<1KB,买断);
- 用户的郑重时刻 → 提示词文件/斜杠命令(确定性触发,租用);
- 模型相机行事 → skill(意图识别触发,按需加载);
- 事件必然发生 → hook(SessionStart/Stop,锁)。

一句话:**提示词是租,常驻是买,代码是锁。低频重活租着用,高频纪律买断,不容违反的上锁。**

## 逐问的完整推理(含被否方案)

**① "为什么不做成可执行程序?"** 因为五个命令的本质全是判断。反证:我们把所有可判定的部分
都写成了代码——doctor(装没装好)、Stop hook 三道闸(证据新鲜度/wiki字段有无/.brain 干净)、
vault(纯操作)。分界线从未含糊,只是两侧比例因领域而异。

**② "Trellis/OpenSpec 是'指令'为什么可以?"** 拆开看是误会:它们的斜杠命令同样是 markdown
提示词文件(OpenSpec 装进 `.claude/commands/openspec/`),与我们机制完全相同。真正的差异是
它们**额外带 CLI 二进制**——因为它们的领域对象强结构化(spec 有 schema 可 validate、任务有
状态机),存在"代码可判定的对象"。我们的领域对象(接收协议质量、认知价值)不可 schema 化,
所以现阶段不配 CLI。**被否方案:自带 CLI**。否决理由:引入一个用户要装要学要升级的实体,
违反零新增概念哲学;触发条件写明——某环节结构化了(如 evidence lint)再上,不预铺。

**③ "/compact 是执行逻辑,init 不是一个道理吗?"** 不是,差在权限层级。/compact 的本质步骤是
**改写客户端自身的上下文窗口**——特权状态操作,只有宿主进程能做,且厂商不向第三方开放原生
命令注册。而且 /compact 内部同样是发提示词(总结那步交给模型),原生代码只包了前后两段状态
操作。反观 brain-init 的每一步(读文件/跑命令/写文档/commit)都是模型经普通工具就能做的事,
**没有一步需要特权**——即使拿到原生命令 API,实现仍会是"把这份协议发给模型",只是多个把
文本藏起来的壳。用户真正想要的"封装感"是 UI 折叠问题(Claude Code 折叠,codex 铺屏),
不是架构问题。

**④ "为什么不用 $trellis-start 那种 skill 形态?"** 用了——v0.3.6 起五命令双形态发布
(prompts + 安装器从同一源文件生成的 SKILL.md)。这里曾犯过一个被用户抓住的错:我声称
"Trellis 也是双发,殊途同归"——**不准确**,Trellis 的命令和 skill 承载不同流程,真正双发同一
流程的是我们。由此引出冗余辩论,定论:源头唯一(skill 由安装器从 commands/*.md 生成,
不存在第二份真相),冗余只在 artifact 层;心智模型收敛为"说人话即可,斜杠是保底"。
**被否方案:revert skill 形态保持极简**。否决理由:用户要的紧凑显示只有 skill 形态给得了,
且老版本 codex 不支持 skill 时 prompts 是唯一通路——降级路径的冗余不是过度设计。

**⑤ 后续演化印证**:codex 0.146 实测证明 hook 层可迁移(其 hook I/O 刻意兼容 Claude 语义,
见 [[codex-hooks-mechanism]]),于是"锁"这一层从 Claude 独占扩展到 codex——决策链没变,
只是"锁"的可用范围随宿主能力扩大。这佐证了按性质分层的稳健性:宿主能力变化时,
迁移的是格子里的东西,不是决策框架本身。
