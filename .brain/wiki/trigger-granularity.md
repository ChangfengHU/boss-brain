# trigger-granularity — 写入跟状态变化,加载分三档

## 问题
"是不是每次对话都要记日志?"——这是这类系统烦不烦的分水岭。

## 结论
**写入**判定一句话:会话产生了 commit/任务状态变化才写;纯问答零写入零仪式。dev-log 不是独立动作,从 evidence 生成。LESSONS 只在真踩坑后写。

**加载**分三档:
- L0 常驻(<1KB):宪法(全局配置文件承载,每次会话无条件进上下文)——这就是"每次都要生效的要求"的实现机制,不靠嘱咐;
- L1 按任务(开工才加载):当前任务上下文,SessionStart hook + 绑定触发;
- L2 按需检索(永不常驻):wiki 词条、历史 evidence、旧任务——skill 懒加载 + index 先行。

接手包(/takeover 加载的密钥位置/规范/机器清单)是特殊的一次性重量级加载:每个新 agent 每个项目手动执行一次,不随会话重载。
