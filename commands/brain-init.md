---
description: 给一个已存在/运行中的项目接入 project-brains——从现有资料长出 brain,而不是空模板
---

对当前工作空间执行 brain 接入(用户明确要求为存量项目初始化时使用)。原则:**从项目已有的资料里蒸馏,不铺空模板**。

1. **前置检查**:已有 `.brain/` → 改为体检并汇报,不重复初始化;有 `.brain-home` → 提示 brain 托管在别处,去归属仓库操作;项目已有自己的文档体系(如控制平面式仓库)→ 优先复用既有文件,用符号链接接入 `.brain/`,不制造第二份真相。
2. **考古**:读 README、已有文档目录、`git log --oneline | head -50`、CI/部署脚本,弄清:这是什么、跑在哪、怎么部署、怎么验证、有什么约定。
3. **凭据与依赖发现(核心步骤)**:系统性推断"这个项目要运转需要什么",线索源:
   - 代码中的环境变量读取(`process.env.*` / `os.environ` / `getenv`)、`.env.example`、config 模板;
   - CI/部署脚本里的 secrets 引用、ssh/scp/rsync 目标机器、registry 登录;
   - SDK/API 初始化(Cloudflare、GitHub、OSS/R2、微信、支付等)与硬编码的服务端点。
   产出**接手需求清单**:机器(IP/用户/SSH 方式)、仓库(读写权限/token)、云账号、三方 API key、运行时服务。
   然后逐项做**缺口检查**:本地已有(标注位置)还是缺失;**缺失但接手必需的,当场逐项向用户索要**
   (要值或要"从哪拿"的指引)。拿到的值只落 `secrets/private/`(600 权限)并在索引/HANDOFF 记名字、
   位置、用途——**值绝不进文档**;项目若配置了 vault,提议同步一份。
4. **生成 `.brain/HANDOFF.md`**(接收协议五段:这是什么/资产与访问/阅读顺序/如何验证已接管成功/雷区);
   第 3 步的需求清单写进"资产与访问"段,它就是下一个接手者的地图:
   - 能从资料确认的写进去;确认不了的写成明确的 `TODO(问用户: ...)`,并当场把这些问题问出来;
   - 验证命令必须**真实跑通**再写入;
   - 密钥只写位置与获取方法,绝不写值;若项目适用密钥保险库,写入 vault 指引。
5. **登记**:向 `~/.project-brains/registry.tsv` 追加一行。
6. **可选沉淀**:项目已有的经验类文档(troubleshooting、FAQ、坑记录)提议蒸馏为 `.brain/wiki/` 首批词条(逐篇征求用户同意,不强推)。
7. **收尾**:commit(本地);**push 必须先问用户**——报出目标远端与分支,用户同意才推,不同意/未回答则明确告知"已 commit 未 push"。汇报生成了什么、需求清单缺口还剩哪些待用户补答。

不做的事:不建 TASKS/LESSONS/evidence 空文件(按需生长);不改动项目任何业务代码与既有文档内容。
