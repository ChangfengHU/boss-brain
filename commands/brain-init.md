description: 给一个已存在/运行中的项目接入 project-brains——从项目资料+会话历史+真实环境三源蒸馏出 brain,而不是空模板
---

对当前工作空间执行 brain 接入(用户明确要求为存量项目初始化时使用)。原则:**三源考古(文件/会话/环境),分类落盘,不铺空模板**。

1. **前置检查**:已有 `.brain/` → 改为体检并汇报,不重复初始化;有 `.brain-home` → 提示 brain 托管在别处,去归属仓库操作;项目已有自己的文档体系 → 优先复用既有文件,用符号链接接入,不制造第二份真相。

2. **文件考古**:读 README、文档目录、`git log --oneline | head -50`、CI/部署脚本,弄清:这是什么、跑在哪、怎么部署、怎么验证、有什么约定。

3. **会话考古(必做,与文件考古同级)**:把当前 Session 历史作为正式信息源,系统性提取九类:
   ①用户的长期目标 ②已确认的开发与协作规范(含"谁执行什么"的职责边界) ③任务三态(已完成/进行中/未开始) ④已体验过的工具/插件及结论 ⑤下一步计划与验收标准 ⑥已确认的机器/服务/目录/认证位置 ⑦用户明确拒绝过的方案及原因 ⑧尚未解决的问题与阻塞 ⑨口头约定的雷区。
   - **不得复制聊天原文,蒸馏为结构化事实**;临时讨论和已废弃想法不沉淀。
   - **完整性边界**:会话被压缩过时,当前上下文只是摘要——先找原始记录补全
     (Claude Code: `~/.claude/projects/<项目slug>/*.jsonl`;codex: `~/.codex/sessions/<日期>/rollout-*.jsonl`;pi: `~/.pi/agent/sessions/`),没有则明示"仅基于压缩摘要,可能有漏"。
     若本流程运行在无历史的独立 subagent 里,必须要求主会话显式传入历史,不得静默跳过。

4. **凭据与依赖发现**:从代码环境变量读取、`.env*`、CI secrets、ssh/scp 目标、SDK 初始化中推断"项目运转需要什么",产出**接手需求清单**(机器/仓库/云账号/API key/运行时服务);逐项缺口检查:本地已有(标位置)或缺失(**当场逐项向用户索要**值或获取指引)。拿到的值只落 `secrets/private/`(600),文档只记名字/位置/用途。

5. **密钥入库(vault,解决换机交接)**:发现本地存在明文密钥(`.env`、私钥、token 文件)时,**必须提议**:
   - 迁移进 `secrets/private/`(700/600),原位置留符号链接保兼容;
   - 执行 `~/.project-brains/vault.sh push <secrets-dir> <vault-url>` 推密文到远端(向用户当场要一次口令,口令不落任何文件);vault-url 用 `https://skill.vyibc.com/<项目名>/vault` 约定,写入 `secrets/VAULT.md` 与 HANDOFF;
   - 用户拒绝则记录"密钥仅存本机,换机需人工搬运"为已知风险。**没有这步,换机器时密钥断层,交接不成立。**

6. **分类落盘**(会话与文件考古的产出各归其位,不许全塞 HANDOFF):
   | 信息 | 去处 |
   |---|---|
   | 世界结构/机器/服务/接管方法/雷区 | `HANDOFF.md`(五段模板,验证命令必须实跑过) |
   | 任务三态与学习进度 | `TASKS.md` |
   | 长期协作规则/开发流程/职责边界 | `CONVENTIONS.md`(首条规范出现时创建) |
   | 高重获成本结论/被拒方案及原因 | `wiki/` 词条 |
   | 密钥值 | `secrets/private/` + vault |
   | 未确认内容 | `TODO(问用户:...)` 并当场问 |
   **冲突优先级**:真实运行状态 > 代码与配置 > 用户最新明确决定 > 旧会话记录。三源交叉验证,以高优先级为准并记下矛盾。

7. **覆盖度自检**(收尾前必须输出):目标/进度/规范/资产/凭据位置与 vault 状态/历史决策/阻塞项/下一步——逐项标"已落盘到哪 / 无此类信息 / 待用户补答",不许留未分类的漏项。

8. **登记与收尾**:registry 追加一行;写入并入 commit(本地);**push 前征得用户同意**;汇报生成了什么、需求清单与覆盖检查还剩哪些待用户补答。

不做的事:不建空文件(按需生长);不改项目业务代码与既有文档内容。
